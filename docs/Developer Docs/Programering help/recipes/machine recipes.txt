Create Expansion - CE Machine Recipes
=====================================

CE recipes use `RecipeDefinition`; Create kinetic recipes keep their existing Create builders.
Put CE recipe files in `recipe/recipes/<recipe_name>`.

```java
import net.mads.createexpansion.recipe.RecipeDefinition.Option;

RecipeDefinition.recipe()
        .recipeDefinition(Option.id("cobblestone_to_stone"))
        .recipeDefinition(Option.recipeType(CERecipeTypes.TEST_STEAM_MACHINE))
        .recipeDefinition(Option.inputItem(Items.COBBLESTONE, 1))
        .recipeDefinition(Option.outputItem(Items.STONE, 1))
        .recipeDefinition(Option.duration(100))
        .save(output);
```

Available option groups include:

- item/tag/fluid inputs and non-consumable inputs
- normal and chanced item outputs and fluid outputs
- duration and consumed/generated CE/t
- minimum electric or kinetic tier
- circuit, temperature, RPM range, and supported recipe logic

`RecipeDefinition` validates all IO counts and capabilities against its `RecipeTypeDefinition`.
The generated JSON still uses `create_expansion:machine` with a `recipe_type` field, so both
singleblocks and CE multiblocks consume the same recipe data through `CERecipeLogic`.

IndustrialMaterials generation
------------------------------

IndustrialMaterials-generated CE recipes also use `RecipeDefinition`. Create processing recipes
generated from IndustrialMaterials continue to use their existing Create recipe builders.

Deferred
--------

Recipe `BlockInteraction` and biome, weather, time, dimension, and altitude conditions are not
implemented yet.
